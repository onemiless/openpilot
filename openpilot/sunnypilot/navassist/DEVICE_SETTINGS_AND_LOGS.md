# 设备导航设置与独立日志

设备设置原 OSM 入口替换为“导航辅助”。OSM 数据文件、已有地图服务和三套纵向核心没有删除或重写。

设置保存于 C3XL `/data/navassist/settings.json`。使用独立 JSON 文件，避免为导航面板重建底层 Params 库。UI 只在 offroad 接受调整；导航进程读取有范围校验的缓存值。缺少配置时使用现有默认行为，读取出错保留本进程上次有效值并在面板显示错误。

| 设置 | 默认 | 范围 |
| --- | --- | --- |
| 导航联动总开关 | 开 | 开/关 |
| 导航自动靠边变道 | 开 | 开/关 |
| 转弯提前打灯 | 开 | 开/关 |
| 导航转弯减速 | 开 | 开/关 |
| 普通路口靠边提前距离 | 1000 m | 100–1500 m，步长 50 |
| 出口/匝道靠边提前距离 | 2000 m | 300–3000 m，步长 100 |
| 转弯打灯提前时间 | 8 s | 3–12 s |
| 普通左/右转目标速度 | 18 km/h | 10–30 km/h |
| 同一事件连续变道次数 | 5 | 1–5 |
| 独立导航日志 | 开 | 开/关 |

总开关关闭仍接收并展示路线；停止导航来源的变道、转弯灯和转弯速度目标。转弯灯开关不影响变道所需的物理灯，也不取消进入路口前停止新增靠边的阶段判断。普通转弯目标不改变掉头、急转和匝道的独立速度。次数上限也约束最终分叉阶段。高德 laneInfo 与启发式靠边使用相同提前距离窗口。

导航层仍只提供高层请求与较低速度目标；实际变道由 SP 执行，实际减速由当前所选纵向执行。

## 独立记录

- 记录服务：`nav_diagnosticsd`，在 C3XL 由现有 manager 管理，独立于导航接收和控制进程。
- 目录：`/data/media/0/navdiagnostics`（如配置其他日志根目录，使用相邻 navdiagnostics）。
- 文件：`navdiag-<开始毫秒>-<结束毫秒>-<随机标识>.jsonl.gz`。
- 文件每 60 秒或 8 MiB 原始内容轮转；保留最多 180 个文件，128 MiB 总预算中预留当前写入块空间。中断残留文件也参与预算，未完成文件不直接下载。
- onroad 按记录循环 20 Hz 采样，offroad 按 1 Hz 记录连接状态。真实信号采样率与时效另存 health，不能把重复记录当作新的模型输出。
- 每个文件都有 metadata：导航设置、设备版本、纵向模式和关键 SP/灯光配置。只使用 Params 白名单，不保存 Key/Token/私钥。
- 每条 sample 带墙钟、单调时钟、各源时间戳及 seen/alive/valid、来源年龄。
- 内容包含 navAssistStateSP、navLaneIntentSP、laneTopologyStateSP、模型 desireState/变道状态/turnDirection、实际灯/盲区/踏板、车速/方向盘、横纵向启用状态、请求曲率与实际曲率、所选速度来源及 SCC-V/TN 状态。
- UDP 收包、接受、按原因拒绝的累计计数和最近收包时间单独记录；接收器每秒写一次 RAM 状态，日志服务读取。不保存 UDP 原文或鉴权材料。
- 不保存视频、原始 CAN、完整模型张量或其他功能日志。

新录制的三类导航专用消息不再写入普通 spdiagnostics；共用车辆状态仍按原有机制保留于普通驾驶日志。更新前的旧混合文件保持原样，不删除或自动迁移。

## 网页下载

浏览器打开 `http://设备IP:8088` → “导航日志”。选择时间范围后独立下载 ZIP；其中只有 `manifest.json` 与 `navigation/*.jsonl.gz`。普通日志的原下载入口继续独立存在。

“刷新最近记录”及下载前会请求记录进程结束当前文件，避免必须等满一分钟才能取得刚发生的问题。下载遵循现有网页 offroad 规则。按相交文件选择范围，每个文件覆盖最多约一分钟，并非逐条裁切。

接口：

- `GET /api/navigation/logs/status`
- `GET /api/navigation/logs/preview?start_ms=...&end_ms=...`
- `POST /api/navigation/logs/flush`
- `GET /api/navigation/logs/download?start_ms=...&end_ms=...`

ZIP 直接流式输出，已压缩文件不二次压缩。扫描拒绝符号链接和无关文件名；读取时使用 O_NOFOLLOW 并复核文件大小/修改时间。

日志用于排查状态和时序。模型输入的原始单帧脉冲未另增 cereal 消息，记录的是模型输出概率、SP 转弯方向、导航请求及对应时钟；不能把这些字段误称为完整模型输入录像。
